# 拾荒掉落类型配额设计

## 目标

把拾荒掉落从"双层倍乘"改为"分层配额"分布：高价值层（价值 ≥ 阈值）合计约 85% 掉落占比、按类型配额内部分配；中低价值层合计 15% 作填充。消除单物品垄断（当前 nudka ≈ 26%、模块提取器/焊接器各 ≈ 13%），同时保证高价值物品出现率保持高位。

### 根源诊断（为什么现状不均衡）

- 内层 ×100 倍乘保留表内相对比例：每张表只有"价值 ≥ 表内最高 × 0.6"的物品被放大，不达标的保持原权重 → 每表唯一的达标物品垄断该表（食品表 nudka 占表内 ~83%，全局 ~26%）。
- junkTable 未被外层增强但基数大（0.637），表内损坏模块/刮刮乐被 ×100 → 各 ≈ 4%。
- 类型倍率只能整体偏移，无法精确控制单物品概率。

## 配置（ScavengingTweaks 分类）

- `DropTypeShares`：string，默认 `"MODULE:25,TOOL:25,FOOD:10,ALCOHOL:10,MEDICAL:5,MATERIAL:5,WEAPON:5"`。语义为**高价值层内部**的类型配额（百分比）。
- `LowTierShare`：int，默认 `15`。中低价值层（10 ≤ 价值 < HighValueFloor）合计占比。
- `HighValueFloor`：int，默认 `60`。高价值层价值下限。
- `QuotaModeEnabled`：bool，默认 `true`。`false` 时退回现有倍乘逻辑（`HighValueMultiplier`/`ItemTypeMultipliers` 照旧生效）。

### 分配规则

1. **排除**：价值 < 10 的物品不参与任何分配（沿用现有垃圾屏蔽）。
2. **分层**：价值 ≥ `HighValueFloor` 进高价值层；其余进低端填充层。**高价值层实际占比恒为 100 − `LowTierShare`**，与 `DropTypeShares` 配置 Σ 无关。
3. **归桶**：物品按其运行时类型列表，取在 `DropTypeShares` 中**最先命中**的类型归桶（多类型物品的归属由配置串顺序决定）。
4. **空桶再分配**：某类型桶内没有合格物品时（当前食品/材料/医疗/武器最高价值均 < 60），该桶配额清零，剩余桶在层内按比例归一；对游戏更新稳健（新增高价值物品后桶自动生效）。
5. **层内均分**：同桶物品均分桶份额；低端层物品均分 `LowTierShare`。
6. **万分比精确性**：份额取整数万分比，用最大余数法保证 Σ 恰好 = 10000。

### 默认值下的预期分布

非空桶 MODULE:25 / TOOL:25 / ALCOHOL:10 归一后 ≈ 35.4% / 35.4% / 14.2%（高价值层 85%）：

- 模块提取器 / 焊接器 ≈ 17.7% 各；nudka ≈ 14.2%；每件模块 ≈ 5.9%
- 低端填充合计 15%，单件约 0.5~2%
- 高价值物品（≥60）合计出现率 ≈ 85%（现状约 70%，且单物品垄断被消除）

## 算法

1. 拾荒窗口打开时（现有补丁时机），枚举全部 9 张表的物品。
2. 排除 value < 10 → 分层 → 归桶（多类型优先级）→ 空桶再分配 → 计算每件物品的全局目标份额（**万分比整数**，保证 Σ 恰好 = 10000）。
3. **直接写入**：物品 `m_BaseProbability` = 全局份额；外层表 `m_BaseProbability` = 表内物品份额之和。两层归一后 P(物品) = 份额，数学精确。
4. 权重恢复沿用现有 `pendingRestores` 机制（拾荒窗口关闭时还原原值）。

## 代码组织

- 新文件 `DropSharing.cs`（纯逻辑，无游戏依赖，进离线测试）：
  - `ParseShares`：配置解析、归一、未知类型忽略；
  - `AssignBuckets`：多类型物品按配置优先级归桶；
  - `ComputeShares`：分层、空桶再分配、万分比份额计算。
- `Mod.cs`：`QuotaModeEnabled` 分支接入现有内层权重调整处；外层表权重写入；物品类型解析复用现有 `itemIdToTypes`。
- 测试：`ScavengingTweaks.Tests` 新增 DropSharing 用例（配额解析、桶分配、Σ=10000 精确性、value<10 排除、多类型优先级、空桶再分配）。

## 诊断与验收

1. 首次生效时日志打印"目标分布表"：每个桶的配额、物品数、每件物品的全局概率。
2. 游戏内实测 20+ 次拾荒：无单物品 > 20% 垄断；高价值合计 ≈ 85%。
3. `QuotaModeEnabled=false` 时回到现有多倍产行为。
4. 价值 < 10 的物品不出现。
5. 离线测试全部通过。

## 兼容

- `MaxAttempts`、伤口屏蔽、地面网格放大、隐藏挎包机制均不受影响。
- 旧配置 `HighValueMultiplier`/`ItemTypeMultipliers` 仅在 `QuotaModeEnabled=false` 时参与计算。
- 不修改游戏原始 DLL、资源包或存档。
